# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project Overview

Docker Compose-based self-hosting bundle that deploys one fixed privacy-focused service set on a VPS. The host configuration is Bash + Docker Compose + YAML. Tailscale is the only ingress after setup. An experimental Go CLI (`runctl`) is retained for the later catalog/plan MVP phase but is not the current public setup path. Supported families are Ubuntu, Debian, and Amazon Linux with systemd.

## Commands

```bash
# One-line remote install (downloads repo + runs fixed setup)
curl -sL <url>/install.sh | sudo bash

# Opinionated fresh-server setup (fixed service list)
sudo bash setup-server.sh

# Experimental runctl MVP
make build
./bin/runctl catalog validate

# Internal setup (auto-generates everything with fixed defaults)
sudo bash scripts/setup.sh

# Start/stop
docker compose up -d
docker compose down

# Update all services
docker compose pull && docker compose up -d

# Health check
bash scripts/test.sh

# Backup (full = stops containers, hot = no downtime)
sudo bash scripts/backup.sh
sudo bash scripts/backup.sh --hot

# Restore (works on fresh server or existing)
sudo bash scripts/restore.sh /path/to/backup.tar.gz.enc

# Logs
docker compose logs -f <service>   # e.g., paperless, jellyfin
```

## Architecture

- **docker-compose.yml** — Single compose file. Services use Docker Compose profiles for selective deployment. NPM (Nginx Proxy Manager) has no profile and always starts.
- **install.sh** — Thin bootstrap for curl-pipe-bash install. Clones repo, hands off to setup-server.sh.
- **setup-server.sh** — Canonical opinionated fresh-server entrypoint. Enforces Ubuntu/RAM/disk requirements and installs the fixed MVP service list.
- **cmd/runctl/** and **internal/** — Experimental catalog/plan/install/status MVP retained for the next phase; do not route the opinionated setup through it yet.
- **registry/** — Experimental application manifest used by `runctl`.
- **scripts/setup.sh** — Internal setup engine. Installs Docker, generates passwords, creates dirs, configures firewall, generates homepage config, starts containers, and runs the health gate.
- **scripts/lockdown-vpn.sh** — Removes public SSH and Docker ingress after verified Tailscale access, and installs a persistent systemd lockdown.
- **scripts/generate-homepage.sh** — Regenerates `configs/homepage/services.yaml` based on enabled profiles and domain from .env.
- **scripts/test.sh** — Profile-aware health check (containers, HTTP endpoints, DNS, Tailscale, resources).
- **scripts/backup.sh** — Creates encrypted, checksummed backups of Docker volumes, bind-mount data, and config. Supports `--hot` mode with pg_dump for no-downtime backups.
- **scripts/restore.sh** — Validates, decrypts, and restores a backup archive using the current release definition.
- **.env.example** — Template. All passwords use `CHANGE_ME_*` placeholders that setup auto-replaces with `openssl rand`.
- **configs/homepage/** — Homepage dashboard YAML configs (regenerated by generate-homepage.sh).

## Docker Compose Profiles

Compose profiles remain an internal implementation detail. The public setup always starts the fixed profile set.

| Profile | Services | Port(s) |
|---------|----------|---------|
| (none/always) | Nginx Proxy Manager | 80, 443, 81 |
| docs | Paperless-ngx, Postgres, Redis, Gotenberg, Tika | 8000 |
| media | Jellyfin | 8096 |
| dns | AdGuard Home | 53, 3000 |
| passwords | Vaultwarden | 8080 |
| monitoring | Uptime Kuma | 3001 |
| dashboard | Homepage | 3002 |
| vpn | Tailscale | host network |

## Network Topology

- **proxy** (`privacy-stack`) — Shared network for services needing external/NPM access
- **paperless** — Internal-only for Paperless + its dependencies
- Tailscale uses `network_mode: host`

## Key Conventions

- All passwords are auto-generated by setup — never require manual editing. The wizard and `--non-interactive` mode both produce a complete .env with random passwords.
- `credentials.txt` is generated alongside .env with human-readable credentials (chmod 600, gitignored).
- Container names use underscores where needed (`uptime_kuma`); Compose service names use hyphens (`uptime-kuma`).
- Service-internal ports (databases, Redis, Tika) are never exposed to the host.
- The `has_profile()` helper function is used across all scripts to conditionally run profile-dependent logic (firewall rules, health checks, homepage entries).
- Backup manifest (`manifest.json`) is included in every backup archive for restore compatibility checking.
